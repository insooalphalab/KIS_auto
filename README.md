# 한투API 자동화 파이프라인 — 2026-09 최적화판

기존 시스템을 검토해서 합의한 5가지 최적화(불필요 파일 정리 / 시간별 수집 빈도 축소 /
일별 심화지표 API 낭비 제거 / 매크로 스크립트 주기를 주간→월간으로 수정 / 다운샘플링을
수집 단계로 이동)를 모두 반영하고, 분석 엔진을 **Gemini API → Claude Code CLI**로
교체했습니다. 아래 순서대로 설치하면 됩니다.

---

## 1. 무엇이 바뀌었나

| 항목 | 이전 | 이후 |
|---|---|---|
| 시간별 수집 빈도 | 평일 7회 (모듈 6개) | 평일 3회: 10:00 / 13:00 / 15:20 (모듈 4개) |
| 매물대·회원사동향 | 시간별 모듈 | 일별 수집으로 이동 (스냅샷 1일 1회면 충분) |
| 일별 심화지표 | 종목당 최대 120일치 분봉 API를 매번 재호출 | 시가/고가/저가 지표 2개는 이미 있는 일봉으로 즉시 계산, 나머지 2개는 `_cache/`에 캐싱되어 신규 거래일만 API 호출 |
| 매크로/섹터 분석 | `주간_섹터_동향분석.py`, 스케줄러가 "월간"이라 부르며 실제로는 매주 일요일 실행 | `월간_매크로섹터분석.py`, 매월 1회 실행, 출력 폴더도 `WeeklyData`(종목별 주간데이터)와 완전히 분리된 `MonthlyMacroData`로 이동 |
| `한투API_월간데이터.py` | 스케줄러 어디서도 호출되지 않는 고아 스크립트 | **삭제 대상** (아래 3번 참고) |
| 다운샘플링(행 축소) | 분석기(AI 호출 직전)에서 수행 | 수집기 단계에서 필요한 양만 수집 — 그리고 Claude Code는 로컬 파일을 직접 읽으므로 애초에 이 단계 자체가 사라짐 |
| AI 분석 엔진 | Google Gemini API (Gemini File 업로드 → 분석 → 삭제) | **Claude Code CLI**(`claude -p ...`)를 이 데스크탑에서 비대화형으로 호출. 데이터 폴더를 작업 디렉터리로 지정해 Claude Code가 xlsx를 직접 읽음 |
| 실행 트리거 | 스케줄러 내부 `while True` 상주 루프 | **Windows 작업 스케줄러**가 정해진 시각에 스케줄러 스크립트를 1회성으로 호출 (컴퓨터가 꺼져 있으면 그 회차만 건너뜀, 상주 프로세스 없음) |

## 2. 파일 구성

### 이 폴더에 포함된 새 파일 / 수정된 파일

- `한투API_시간별데이터.py` — 4개 모듈로 축소
- `한투API_일별데이터.py` — 심화지표 캐싱 + 매물대·회원사동향 탭 추가
- `한투API_주간데이터.py` — **변경 없음** (종목별 주간 수급, 토요일 실행 그대로 유지)
- `월간_매크로섹터분석.py` — 구 `주간_섹터_동향분석.py`, 월간 주기로 전환
- `한투API_텔레그램분석.py` — Gemini → Claude Code CLI 기반으로 전면 교체
- `한투API_스케줄러.py` — 시간별 3회, 월간 스크립트/폴더명 갱신, Task Scheduler 연동용 1회성 호출 지원
- `setup_tasks.ps1` — Windows 작업 스케줄러 등록 스크립트
- `remove_tasks.ps1` — 등록 제거 스크립트
- `tickers.json` — 변경 없음 (참고: 보유상태 비중 합이 109%로 100%를 넘습니다 — 실제 반영 비중과 다르다면 한 번 점검해보시는 걸 권합니다)

### 기존 폴더에서 정리할 파일

- `한투API_월간데이터.py` — **삭제 또는 백업 폴더로 이동**하세요. 스케줄러 어디서도 호출되지 않는
  고아 코드였고, 대체 기능(월간 매크로 분석)은 `월간_매크로섹터분석.py`가 담당합니다.
- `주간_섹터_동향분석.py` — `월간_매크로섹터분석.py`로 대체되었으니 삭제하거나 백업하세요.
  (기존에 쌓인 `WeeklyData/` 안의 `Macro_Weekly_*.xlsx`, `SectorAction_*.xlsx` 과거 데이터는
  그대로 두셔도 무방합니다. 앞으로의 매크로 산출물은 새 폴더 `MonthlyMacroData/`에 쌓입니다.)

## 3. 설치 순서

### 3-1. Claude Code CLI 설치 & 로그인 (이 컴퓨터에서, 최초 1회)

1. Node.js가 설치되어 있는지 확인: `node --version`
2. Claude Code 설치: `npm install -g @anthropic-ai/claude-code`
3. 설치 확인: `claude --version`
4. **반드시 사람이 직접 로그인까지 마쳐야 합니다.** 터미널에서 `claude` 를 한 번 실행해
   로그인 절차를 끝내세요. (작업 스케줄러는 사람이 없어도 실행되므로, 로그인 인증이
   이 계정 프로필에 저장되어 있어야 무인 실행이 가능합니다.)
5. **중요 — 반드시 확인**: `claude --help` 를 실행해서 아래 두 플래그의 정확한 이름을
   확인하세요.
   - 비대화형 출력 형식 플래그 (코드에서는 `--output-format json` 사용 — 결과와 토큰 사용량을 함께 받아 `claude_usage.jsonl` 에 누적 기록)
   - 승인 절차 건너뛰기 플래그 (코드에서는 `--dangerously-skip-permissions` 로 가정)

   설치된 버전에서 이름이 다르면 `한투API_텔레그램분석.py` 상단의 아래 줄만 고치면 됩니다.
   ```python
   CLAUDE_EXTRA_ARGS = ["--output-format", "json", "--dangerously-skip-permissions",
                        "--disable-slash-commands", "--strict-mcp-config", "--no-session-persistence"]
   ```
   `--disable-slash-commands` / `--strict-mcp-config` 는 스킬 목록·MCP 커넥터 설명이 시스템
   프롬프트에 실리는 것을 막아 호출당 약 6,000 토큰을 줄입니다 (분석에는 불필요한 기능).
   `claude` 명령이 PATH에 안 잡히면 같은 파일의 `CLAUDE_CLI = "claude"` 를 전체 경로로
   바꾸면 됩니다 (예: `claude.cmd` 전체 경로).

   > ⚠️ `--dangerously-skip-permissions` 는 도구 사용 승인을 전부 건너뜁니다. 무인
   > 스케줄 실행에는 필요하지만(승인해 줄 사람이 없으므로), 그만큼 신뢰를 전제로 하는
   > 설정이라는 점은 알고 계시는 게 좋습니다. 작업 디렉터리를 그 회차의 데이터 폴더
   > 하나로 한정해 두었으니 실질적인 위험 범위는 작습니다.

### 3-1-1. 시크릿(.env)과 개인 포트폴리오 설정 — GitHub 공유 시 필수

API 키·계좌번호·텔레그램 토큰은 코드에 들어 있지 않고 프로젝트 루트의 `.env` 에서 읽습니다
(`kis_config.py` 가 로드). `.env` 와 `tickers.json`(보유 종목·비중), 수집 산출물(`MarketData/` 등)은
`.gitignore` 로 git 에서 제외되어 있습니다.

새 환경(또는 저장소를 clone 한 뒤)에서는:

```
copy .env.example .env               # 열어서 실제 키 값 입력
copy tickers.example.json tickers.json   # 열어서 본인 종목/비중으로 수정
```

- `.env` 항목: `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_CANO`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
  `FRED_API_KEY`, `CUSTOMS_API_KEY`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`
- 값이 비어 있으면 해당 스크립트가 어떤 항목이 없는지 알려주며 즉시 중단됩니다.
- OS 환경변수로 같은 이름을 설정해 두면 `.env` 값보다 우선합니다.

### 3-2. 파일 배치

이 패키지의 파일들을 기존 프로젝트 폴더(`C:\project1\` 등,
`tickers.json` 이 있던 바로 그 폴더)에 덮어쓰기로 복사하세요.

그런 다음 2번 항목의 "기존 폴더에서 정리할 파일"에 적힌 2개 파일을 삭제(또는 별도
백업 폴더로 이동)하세요.

### 3-3. 동작 확인 (스케줄 등록 전에 먼저)

1. 시간별 1회 테스트
   ```
   python 한투API_스케줄러.py --once
   ```
2. 일별 1회 테스트
   ```
   python 한투API_스케줄러.py --daily
   ```
3. 주간은 수집기 실행 시간이 길 수 있으니 시간 여유 있을 때 테스트하세요. (월간 매크로는 운영 제외)
   ```
   python 한투API_스케줄러.py --weekly
   ```
4. 텔레그램 발송 없이 콘솔에서만 결과를 보고 싶다면 분석기를 직접 `--preview` 로
   실행할 수 있습니다.
   ```
   python 한투API_텔레그램분석.py --preview
   python 한투API_텔레그램분석.py --daily   --preview
   python 한투API_텔레그램분석.py --weekly  --preview
   python 한투API_텔레그램분석.py --monthly --preview
   ```

모두 정상적으로 텔레그램 메시지(또는 콘솔 미리보기)가 나오면 준비 완료입니다.

### 3-4. Windows 작업 스케줄러 등록

1. PowerShell을 **관리자 권한으로 실행**
2. 프로젝트 폴더로 이동 후:
   ```
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
   .\setup_tasks.ps1
   ```
3. `taskschd.msc` (작업 스케줄러)를 열어 `KIS_` 로 시작하는 작업 5개가 보이는지 확인
4. 필요하면 작업을 우클릭 → "실행"으로 수동 트리거해서 한 번 더 확인
5. 나중에 제거하고 싶으면 같은 방식으로 관리자 권한 PowerShell에서:
   ```
   .\remove_tasks.ps1
   ```

## 5. 문제 해결

- **텔레그램에 "Claude Code CLI(claude 명령)를 찾을 수 없습니다" 메시지가 옴**
  → `claude` 가 PATH에 없거나 로그인이 안 된 상태입니다. 3-1번을 다시 확인하세요.
- **"Claude Code 분석이 N초 안에 끝나지 않아 중단되었습니다" 메시지가 자주 옴**
  → `한투API_텔레그램분석.py` 상단의 `CLAUDE_TIMEOUT_SEC` 값을 늘리세요.
- **월간 작업이 "Macro_Monthly_*.xlsx 없음" 오류를 냄**
  → 매월 1일이 주말·공휴일(휴장일)이면 그날 수집기가 데이터를 만들지 못했을 수
  있습니다. 다음 영업일에 수동으로 `python 한투API_스케줄러.py --monthly` 를
  한 번 실행하면 됩니다.
- **일별 심화지표 캐시가 꼬인 것 같음 (숫자가 이상함)**
  → 프로젝트 폴더의 `_cache/advanced_intraday_{종목코드}.json` 파일을 지우면
  다음 실행 때 해당 종목만 처음부터 다시 계산합니다(그 날 1회는 API 호출량이
  평소보다 늘어납니다).
